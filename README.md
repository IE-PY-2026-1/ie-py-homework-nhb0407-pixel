## 🟦 [1차 과제: V1.0] 시나리오 기획
    
# 개발 내용
변수 활용: goods_name (문자열), purchase_price (정수), profit_rate (실수) 등 다양한 자료형을 정의하고 활용했습니다.
형변환(Casting): 파이썬의 input()은 모든 입력을 문자로 취급하기 때문에, 계산을 위해 int()를 사용하여 숫자로 바꾸어 주는 핵심 문법을 포함했습니다.
f-string 포맷팅: f"{variable:,}"를 사용하여 금액에 콤마(,)를 넣었습니다.
##코드 
# =========================================================
# [Resell-Master V1.0] 굿즈 시세 분석 프로그램
# 작성자: (남현빈)
# 과제 목표: 변수 선언, 입출력, 산술 연산을 이용한 프로그램 구축
# =========================================================
# 1. 인트로 화면 출력
print("=========================================")
print("     Goods Market Analyzer V1.0")
print("      나의 굿즈 수집 포트폴리오")
print("=========================================")
print()
# 2. 데이터 입력 (input 사용)
# input()은 기본적으로 문자열로 받으므로, 숫자는 int()로 형변환이 필요합니다.
goods_name = input("1. 분석할 굿즈 이름: ")
purchase_price = int(input("2. 개당 구매 가격(원): "))
market_price = int(input("3. 현재 장터 시세(원): "))
quantity = int(input("4. 보유 수량(개): "))
# 3. 데이터 연산 (에너지/로직 처리)
# 변수를 활용하여 필요한 수치들을 계산합니다.
total_cost = purchase_price * quantity      # 총 투자 금액
total_value = market_price * quantity       # 현재 총 가치
net_profit = total_value - total_cost       # 예상 순수익
profit_rate = (net_profit / total_cost) * 100  # 수익률(%)
# 4. 최종 결과 리포트 출력
print()
print("-----------------------------------------")
print(f"[ 분석 결과: {goods_name} ]")
print(f"- 총 투자 금액: {total_cost:,}원")
print(f"- 현재 총 가치: {total_value:,}원")
print("-----------------------------------------")
print(f"▶ 예상 순수익: {net_profit:,}원")
print(f"▶ 현재 수익률: {profit_rate:.2f}%")
print("-----------------------------------------")
print("※ V2.0에서 조건문(if)을 이용한 등급 판정 기능이 추가될 예정입니다.")
print("=========================================")

### 🛠️ Troubleshooting & 기술 회고

**문제 1: insert 후 인덱스 번호 어긋남**  
- 원인: `goods_names.insert(0, hot_item)`으로 관심 굿즈를 맨 앞에 넣으니 원래 굿즈들이 인덱스 1, 2, 3으로 밀려나 `goods_names[i]`와 `market_prices[i]`가 불일치함.  
- 해결: 출력 시 `goods_names[i+1]`로 오프셋을 +1 적용하여 해결. 리스트 병행 운용 시 insert 위치에 따라 인덱스가 달라짐을 학습함.

**문제 2: float 나눗셈 결과를 int로 오해**  
- 원인: `ratio = market_prices[i] / retail_prices[i]` 계산 시 정수끼리 나눠도 파이썬3에서는 자동으로 float가 됨을 몰랐음.  
- 해결: 파이썬3의 `/` 연산자는 항상 float 결과를 반환한다는 점을 확인하고, `{ratio:.2f}`로 소수점 2자리 포맷팅하여 출력함.

## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템 (반복문)

### ✨ 3차 과제 업데이트 내용

이번 과제는 V2.1 코드를 시세 추이 분석기로 업그레이드했다. 단순히 현재 시세 하나를 분석하던 V2.1에서 벗어나, 일/주/월 단위로 여러 기간에 걸쳐 매물을 입력받고 가격 변화율과 상승·하락 추이를 분석해 최적 매수 타이밍까지 알려주는 주식 HTS 스타일의 시세 분석 프로그램으로 발전시켰다.

가장 핵심적인 구조 변화는 중첩 반복문 도입이다. 바깥 `for`문이 주차를 순서대로 넘기고, 안쪽 `while True` 무한루프가 해당 주차의 매물을 계속 입력받다가 사용자가 "다음 주차로" 를 선택하면 `break`로 탈출하는 방식이다. 덕분에 한 주차에 매물이 몇 개든 자유롭게 입력할 수 있다.

또한 매물 상태를 `거래완료 / 판매중` 으로 구분해 `continue`로 허수 매물을 걸러내고, 실거래 완료된 데이터만 평균가 계산에 반영해 신뢰도 높은 시세 분석을 구현했다.

- 바깥 `for` + 안쪽 `while True` 중첩 반복문으로 주차별 다중 매물 입력 구조 구현
- `break`로 해당 주차 입력 완료 후 다음 주차로 이동, `continue`로 잘못된 입력 및 허수 매물 스킵
- 사용자가 일/주/월 단위를 직접 선택, `if-elif-else`로 라벨과 단위명 분기 처리
- `def get_trend()`, `def get_timing()`, `def get_real_avg()`, `def draw_chart()` 총 4개 함수로 분석 로직 완전 분리
- `get_real_avg(prices, statuses)` 함수가 허수 필터링 + 평균가 계산을 동시에 수행, `return avg, real_list` 로 두 값 반환
- 주차별 평균 실거래가를 `period_avgs` 리스트에 누적 후 구간별 변화율, 상승/하락 횟수, 최대 등락폭 분석
- 직전 2구간 데이터로 "하락 후 반등" 패턴 감지 시 매수 타이밍 신호 출력
- `draw_chart()`에서 `"█" * bar_len` 문자열 반복 연산으로 텍스트 막대 그래프 출력

**내용 2: 허수 시세 필터링 + 주차별 평균가 분석 설계**

- 프롬프트 요약: "팔린 거, 안 팔린 거 구분해서 허수 시세 제거하는 것도 할 수 있어? 몇 일 단위로 변화 추이 나타낼지 사용자가 선택 가능하게 해줘."
- 적용 내용: 매물 상태를 `1=거래완료 / 2=판매중`으로 입력받아 `get_real_avg()` 함수 안에서 `continue`로 판매중 매물을 걸러내고 실거래 완료 데이터만 평균가 계산에 반영하는 구조를 구현함. 기간 단위는 `if-elif-else`로 일/주/월을 분기해 `unit_label`과 `period_name` 변수에 담아 리포트 전체에 재활용함. 단순 현재 시세 분석에서 **시간 축 기반 추이 분석**으로 프로그램이 한 단계 진화함.

**내용 3: 시세 추이 분석 로직 및 매수 타이밍 판단 설계**

- 프롬프트 요약: "몇 일 단위로 변화 추이 나타낼지 사용자가 선택 가능하게 해줘. 주식처럼 가격 변화율과 상승 하락 추이 분석하고 그거 기반으로 매수 타이밍을 알려주게 할 수 없을까?"
- 적용 내용: `get_trend(current, previous)` 함수가 변화율과 방향을 동시에 `return`하고, `for`문 안에서 구간마다 호출해 상승/하락 횟수와 최대 등락폭을 누적 계산하는 구조를 채택함. `get_timing()`은 최근 평균가를 전체 최저가·평균가와 비교해 4단계 매수 등급을 판정하고, 직전 2구간의 등락 방향을 비교해 "하락 후 반등" 패턴을 감지하는 기술적 분석 로직을 구현함.

### 🛠️ Troubleshooting & 기술 회고

**문제 1: 안쪽 while이 break 되어도 바깥 for가 안 넘어가는 것처럼 보이는 현상**
- 원인: `break`는 자신이 속한 가장 가까운 반복문 하나만 탈출함. 안쪽 `while True`를 탈출해도 바깥 `for`문은 계속 정상 동작하는데, 처음에는 둘 다 멈추는 줄 알고 혼란이 있었음.
- 해결: `break`의 적용 범위가 '직속 반복문 하나' 임을 확인하고, 안쪽 `while`을 탈출하면 자동으로 바깥 `for`의 다음 회차(다음 주차)로 넘어간다는 중첩 반복문 동작 원리를 학습함.

**문제 2: 실거래 매물이 0개인 주차에서 `max()`, `min()` 오류 발생**
- 원인: 해당 주차에 판매중 매물만 입력되면 `real_list`가 빈 리스트가 되고, 빈 리스트에 `max()` / `min()`을 호출하면 `ValueError`가 발생함.
- 해결: `get_real_avg()` 함수에서 `len(real) == 0` 조건을 먼저 체크해 빈 리스트면 `return 0, real`로 조기 반환하고, 메인 코드에서 `len(real_list) == 0`이면 해당 주차를 분석에서 제외하는 방어 로직을 추가함.

**문제 3: 잘못된 가격 입력 시 매물 번호가 올라가버리는 현상**
- 원인: `price <= 0` 조건으로 `continue` 처리를 하기 전에 이미 `listing_num += 1`이 실행되어, 유효하지 않은 매물에도 번호가 카운트되는 문제가 발생함.
- 해결: `continue` 직전에 `listing_num -= 1`로 번호를 다시 차감해 유효 매물 번호가 정확히 유지되도록 수정함. 변수 증감 순서가 로직에 미치는 영향을 직접 경험

- **이후 발전 방향**
- 굿즈 하나만이 아니라 여러개를 한꺼번에 리스트업 할 수 있도록 발전.
- 가격을 입력하면 굳이 1을 누르지 않아도 그 주차 가격을 추가할수 있도록 한다.
- 여러 굿즈의 할인율과 가격 변화 추이를 분석해 구매 추천도를 정렬.
- 허수 가격은 아예 입력을 안하는 방향으로
- 만약 굿즈를 판다면 추천 판매가 도출.
- n개월 뒤에 굿즈 가격이 어떻게 될지 예측.
- 컴백 등의 이벤트로 굿즈가격이 상승하거나 하락하는거를 변수계수를 도입해 추이에 추가.

## 🟥 [4차 과제: V4.0] 모듈화 및 데이터 확장 (딕셔너리 + 파일 입출력)

### ✨ 4차 과제 업데이트 내용

V3.0까지는 굿즈 하나만 분석할 수 있었는데, 실제로 수집가들은 여러 굿즈를 동시에 비교하면서 어떤 걸 살지 결정한다. 그래서 이번 V4.0의 목표는 단순히 기능을 추가하는 게 아니라 실제로 쓸 수 있는 프로그램에 가깝게 만드는 것이었다.
가장 크게 바뀐 건 데이터 구조다. 기존에는 굿즈 이름, 정가, 시세를 리스트 3개에 따로 저장했는데, 이번에는 딕셔너리를 써서 굿즈 하나의 모든 정보를 한 덩어리로 묶었다. 덕분에 굿즈가 몇 개든 `for`문 하나로 전체를 한꺼번에 분석할 수 있게 되었다.
가격 입력 방식도 바꿨다. V3.0에서는 매물을 하나 입력하고 나서 "1번 추가, 2번 다음"을 눌러야 했는데, 이게 매물이 많을수록 번거로웠다. V4.0에서는 가격을 입력하면 바로 등록되고, 빈칸으로 Enter를 치면 다음 주차로 넘어가도록 바꿨다. 허수 매물 구분도 없앴다. 어차피 실거래가만 입력받으면 되기 때문이다.
기능적으로는 이벤트 계수, 가격 예측, 추천 판매가, 구매 추천 정렬, 파일 저장까지 추가했다. 처음에는 기능이 너무 많아질까 걱정했는데, 딕셔너리와 함수로 역할을 깔끔하게 나눠두니까 오히려 코드가 V3.0보다 읽기 편해졌다.

- `portfolio` 딕셔너리로 굿즈별 데이터를 독립적으로 관리, `for key, value in portfolio.items()`로 전체 순회 분석
- 가격 입력 즉시 등록, 빈칸 Enter로 다음 주차 이동 — 별도 메뉴 선택 불필요
- 허수 매물 입력 단계 완전 제거 — 실거래가만 입력받는 방식으로 단순화
- `event_coefficients` 딕셔너리에 이벤트별 계수를 저장하고 `apply_event()` 함수로 입력가에 즉시 반영
- `predict_price()` 함수로 선형 추세 기반 n기간 뒤 예측가 계산
- `get_sell_price()` 함수로 평균가·최고가 기반 추천 판매가 도출
- `recommendation` 딕셔너리에 굿즈별 추천 점수를 저장하고 `sorted()`로 구매 추천 순위 정렬 출력
- `save_report()`에서 `with open("w")`로 분석 결과 파일 저장, `try-except FileNotFoundError`로 파일 없을 때 예외 처리

### 🤖 AI 파트너십 과정

**내용 1: 딕셔너리 기반 다중 굿즈 구조 설계**

- 프롬프트 요약: "굿즈 하나만이 아니라 여러 개를 한꺼번에 리스트업 할 수 있도록 발전시키고 싶어. 딕셔너리로 굿즈별 데이터를 독립적으로 관리하는 구조를 짜줘."
- 적용 내용: `{ 굿즈명: { "retail": 정가, "period_avgs": [] } }` 형태의 중첩 딕셔너리 구조를 제안받아 적용했다. 기존에 리스트 3개를 병렬로 굴리던 방식에서 굿즈 하나의 데이터를 딕셔너리 하나에 전부 묶는 방식으로 바꿨더니, `for goods_name, data in portfolio.items()`한 줄로 전체 굿즈를 순회할 수 있게 되어 코드가 훨씬 간결해졌다.

**내용 2: 이벤트 계수 + 가격 예측 + 추천 판매가 함수 설계**

- 프롬프트 요약: "컴백 같은 이벤트로 굿즈 가격이 오르거나 내리는 걸 변수 계수로 반영하고 싶어. n개월 뒤 가격 예측이랑 추천 판매가도 도출해줘."
- 적용 내용: `event_coefficients = {"컴백": 1.35, "해체": 0.50}` 딕셔너리에 이벤트별 계수를 미리 정의하고, `apply_event()` 함수에서 `키 in 딕셔너리`로 유효성 확인 후 계수를 곱해 조정 가격을 돌려주는 구조를 적용했다. 예측가는 전체 구간의 평균 변화량을 n기간만큼 연장하는 방식으로 구현했고, 추천 판매가는 평균가와 최고가의 중간값으로 계산했다.

**내용 3: 파일 입출력 + 구매 추천 정렬 설계**

- 프롬프트 요약: "분석 결과를 파일로 저장하고 싶어. 여러 굿즈의 가격 변화 추이를 비교해서 구매 추천 순위도 정렬해서 보여줘."
- 적용 내용: `save_report()` 함수에서 `with open("w", encoding="utf-8")`로 txt 파일에 저장하고, `try-except FileNotFoundError`로 파일이 없을 때 프로그램이 터지지 않게 방어했다. 구매 추천 정렬은 `get_timing()`이 반환하는 점수를 `recommendation` 딕셔너리에 굿즈별로 쌓아두고, `sorted()`로 내림차순 정렬해 순위를 출력하는 방식으로 구현했다.

### 🛠️ Troubleshooting & 기술 회고

**문제 1: 중첩 딕셔너리 접근 시 KeyError 발생**
- 원인: `portfolio[goods_name]["period_avgs"]`처럼 안쪽 딕셔너리에 접근할 때, 바깥 키가 먼저 존재하지 않으면 KeyError가 났다.
- 해결: 굿즈 등록 시점에 `portfolio[goods_name] = {"retail": ..., "period_avgs": []}` 형태로 안쪽 딕셔너리를 미리 통째로 초기화하고 나서 데이터를 추가하는 순서로 수정했다. 딕셔너리는 키가 존재해야 값에 접근할 수 있다는 걸 직접 에러를 겪으면서 확실히 배웠다.

**문제 2: 빈칸 Enter 입력 시 int() 변환 오류**
- 원인: 빈칸으로 Enter를 치면 빈 문자열 `""`이 반환되는데, 이걸 바로 `int()`로 변환하려니 `ValueError`가 났다.
- 해결: `if raw == "": break`를 `int()` 변환 앞에 먼저 배치해서, 빈칸이면 변환 시도 없이 즉시 탈출하게 했다. 입력값 검사는 항상 형변환보다 먼저 해야 한다는 걸 이번에 제대로 체감했다.
